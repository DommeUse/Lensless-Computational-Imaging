## 1. Что было реализовано

Полная реализация безлинзовой реконструкции с нуля на основе [pytorch_project_template](https://github.com/Blinorot/pytorch_project_template).

### Архитектура

| Компонент | Реализация |
|---|---|
| ADMM (camera inversion) | расщепление переменных $u$, $v$, $w$, $x$ (целевое изображение; выход модели); апдейты по Monakhova Eq.4; вся арифметика в производится в пространстве Фурье для скорости операций, паддинг $\times 2$ для честной линейной свёртки |
| ADMM-100 | классический ADMM, $\mu = 10^{-4}$, $\tau = 2 \cdot 10^{-4}$, 100 итераций, без обучения (бейзлайн) |
| ADMM-Unrolled (Le-ADMM) | 20 итераций, обучаемые $\{\mu_1, \mu_2, \mu_3, \tau\}$ на каждой итерации, лог-параметризация для неотрицательности параметров |
| DRUNet | Взят Apppendix.B Bezzam: strided-conv down, transposed-conv up, аддитивные skip, residual-блоки с ReLU, удвоение каналов; `hidden_channels` управляет ёмкостью ($h = 32 \rightarrow \sim 8.2$ M, $h = 24 \rightarrow \sim 4.6$ M параметров) |
| ModularReconstruction | pre-DRUNet $\rightarrow$ LeADMM (5 итераций) $\rightarrow$ post-DRUNet (`pre`/`post` опциональны, есть эксперименты с рассмотрением их по отдельности) |
| Loss | `LenslessLoss` $=MSE + LPIPS$ (VGG, `normalize = True`), на ROI кропах |
| Метрики | PSNR, SSIM, LPIPS, MSE на ROI кропах; выход модели min-max нормируется для выравнивания яркости |
| Оптимизатор | Adam, lr $= 10^{-4}$ (const), $\beta = (0.9, 0.999)$ - параметры из статьи Bezzam, lr_sheduler = `ConstantLR` |
| Тренировка | $\sim$ 14 эпох на модель, `monitor = max test_PSNR` - критерий выбора лучшей модели, `save_period = 5`, gradient clipping через `max_grad_norm` |

### Три пространства изображений

Ключевой и вызывающий наибольшее число багов момент пайплайна - работа с тремя разрешениями:

- **padded** $760 \times 1014$ - для ADMM/FFT (паддинг $\times 2$, чтобы размеры тензоров при свертке воспали по размерам).
- **sensor** $380 \times 507$ - выход модели, выровненный lensed.
- **ROI** $200 \times 266$ - на нём считаются лосс и метрики.

PSF симулируется из значений SLM-маски (`simulate_psf_from_mask`, библиотека `waveprop`), lensless-измерение поворачивается на `rot90(k = 2)`, ground-truth изображение вписывается в ROI через `get_cropped_lensed`. В реализации использовались функции из набора `lensless_helpers`, который был дан в помощь к этой работе.

### Пять конфигураций моделей

| Config | Модель |
|---|---|
| `admm100` | ADMM-100, eval-only бейзлайн |
| `admm_unrolled` | Le-ADMM, 20 итераций, обучаемые параметры |
| `modular_pre` | DRUNet ($h=32$) $\rightarrow$ Le-ADMM-5 |
| `modular_post` | Le-ADMM-5 $\rightarrow$ DRUNet ($h=32$) |
| `modular_pre_post` | DRUNet ($h=24$) $\rightarrow$ Le-ADMM-5 $\rightarrow$ DRUNet ($h=24$) |

Модульные варианты были сделаны при сопоставимом бюджете параметров ($\sim 8$-$9$ M). Первоначальный подбор $h$ выдал примерно `9.2M` параметров у `Pre-Post` модели, а у `Only-Pre` и `Only-Post` - по `8.2M`. Числа сопоставимые в силу схожих порядок, поэтому эксперименты по точечной подгонке числа параметров не проводились.

## 4. Сложности и баги

В процессе реализации было поймано много содержательных багов, из-за чего пришлось провести большое количество экспериментов - все они залогированы в проект Comet ML: https://www.comet.com/german-zverev/lensless-computational-imaging

> Чтобы проследить весь путь исправления ошибок можно посмотреть в архив экспериментов, куда я скидывал все неудачные попытки. В самом проекте на главной странице оставлены только итоговые чистые эксперименты.

### 4.1. Нормировка выхода ADMM перед подсчётом метрик

ADMM восстанавливает изображение $x$ в произвольном масштабе - выход не лежит в $[0, 1]$. Из-за этого метрики, чувствительные к масштабу, (PSNR и SSIM считаются с `data_range = 1`) выдавали мусор, тогда как LPIPS (внутри клампит вход) и MSE (относительная ошибка) выглядели адекватно.

На ADMM-100 **без нормировки** получались такие числа:

```
Metrics on test set:
PSNR:  6.526
LPIPS: 0.724
MSE:   0.232
SSIM:  0.101
```

LPIPS и MSE - нормальные, остальное - ерунда. Решение: перед подсчётом метрик нормировать выход (min-max по каждому изображению, по осям `(C, H, W)`), чтобы привести всё к одному масштабу.

Фикс выглядит так:
```python
def normalize_img(img):
    mn = img.amin(dim = (-3, -2, -1), keepdim = True)
    mx = img.amax(dim = (-3, -2, -1), keepdim = True)
    return (img - mn) / (mx - mn + 1e-8)
```

**Важный нюанс.** Нормировка применяется **строго после** `loss.backward()` и `optimizer.step()`, а не до. Лосс (в частности MSE) должен видеть **ненормированный** выход и вынужден учить правильную яркость/масштаб изображения; если нормировать до лосса, MSE потеряет сигнал по яркости, от которой сильно страдают результаты ADMM без денойзера. В коде trainer это явный порядок:

```python
all_losses = self.criterion(**batch)   # лосс на сыром выходе
...
batch["loss"].backward()
self._clip_grad_norm()
self.optimizer.step()
...
batch["output"] = normalize_img(batch["output"])  # нормировка только для метрик
for met in metric_funcs:
    metrics.update(met.name, met(**batch))
```

В итоге после нормировки метрики ADMM-100 стали выглядеть сильно лучше:

```
Metrics on test set:
PSNR:  10.898
LPIPS: 0.752
MSE:   0.086
SSIM:  0.279
```

Как мы видим, LPIPS стал чуть хуже, но зато PSNR, SSIM и даже MSE улучшились на порядок. Это является подтверждением правильно нормировки, так как такие метрики сопоставимы с теми, что представлены в статье Bezzam. Есть вероятность, что я не заметил в статье блок про нормировку, но на самом деле она наверняка применялась авторами.

### 4.2. Уход параметров в минус в Unrolled ADMM

В Le-ADMM параметры $\{\mu_1, \mu_2, \mu_3, \tau\}$ - это штрафные коэффициенты ADMM, и они **обязаны быть положительными**: знаменатель шага

$$\text{denom} = \mu_1 |P|^2 + \mu_2 \|\Psi\|^2 + \mu_3$$

должен быть $> 0$, а порог soft-thresholding $\ge 0$. При прямой параметризации Adam на первых же шагах уводил коэффициенты в минус, что было обнаружено при подсчете метрик и логировании параметров, из-за чего происходило деление на $\leq 0$ и отрицательный порог становился NaN $\Rightarrow$ расходимость.

**Фикс**: хранить **лог-параметры** и брать экспоненту:

```python
self.log_mu1 = nn.Parameter(torch.ones(n_iters) * math.log(mu_init))
...
mu1 = self.log_mu1[step].exp()   # всегда > 0
```

Положительность гарантируется автоматически. 

### 4.3. Кеширование PSF

`simulate_psf_from_mask` (через библиотеку `waveprop`) - дорогая операция. Изначально PSF пересчитывалась в **каждом** `__getitem__`, из-за чего обучение еле двигалось. Для сравнения, время одной эпохи составляло более 1,5 часов на A100.

Первая попытка - кешировать внутри ADMM по `mask_label` - не сработала: `collate_fn` не прокидывал `mask_label`, ключ всегда был одинаковый, и по факту весь батч переиспользовал PSF одного изображения (тихий баг с порчей данных). Правильное решение - **кешировать PSF в датасете** по `mask_label` (в переменную `psf_cache`), а в ADMM кешировать только size-only константы по размеру тензора - так мы тоже сэкономим некоторые вычисления.

После фикса скорость стала адекватной: **$\sim 14$ секунд на 50 батчей по 4 элемента на A100** (модель pre-post) и всего **11 минут** на одну эпоху(не считая подсчет тестовых метрик).

### 4.4. Gradient clipping (VIP)

У unrolled-моделей градиенты плохо обусловлены: FFT + много итераций + коэффициенты $\mu \approx 10^{-4}$ дают резкие всплески нормы градиента. Включение `max_grad_norm=1.0` (gradient clipping) дало **очень заметный буст** по сходимости и итоговым метрикам - это хорошо видно при сравнении экспериментов в Comet (с клиппингом и без).

Этот фикс дал, во-первых, сходимость к более большому PSNR, и, во-вторых, более быстрый и резкий старт, из-за чего минимальные пороги PSNR пробивались уже на первых двух эпохах.

## 5. Денойзеры: размещение важнее числа параметров

Абляция pre-only / post-only / pre-post сделана при сопоставимом бюджете параметров (`8.2M` vs `8.2M` vs `9.2M`) - именно для того, чтобы сравнение отражало **место** денойзера в пайплайне, а не разницу в ёмкости. Числа из раздела 3 показывают, что число весов - слабый предиктор качества, а определяющий фактор - архитектурное размещение.

### Идентичная ёмкость, разный результат

`Modular Pre` и `Modular Post` имеют **ровно одинаковое** число обучаемых параметров - 8 167 319 (один DRUNet с `hidden_channels = 32`). При этом:

| | PSNR $\uparrow$ | SSIM $\uparrow$ | LPIPS $\downarrow$ | MSE $\downarrow$ |
|---|---|---|---|---|
| Modular Pre (8 167 319) | 13.335 | 0.219 | 0.634 | 0.050 |
| Modular Post (8 167 319) | 15.953 | 0.431 | 0.550 | 0.028 |
| $\Delta$ (Post - Pre) | **+2.62** | **+0.212** | **-0.084** | **-0.022** |

То есть `Post` буквально по всем метрикам обходит `Pre`.

Разрыв в **2.6** у PSNR при **нулевой** разнице в числе параметров - это и есть прямое доказательство того, что результат определяется не ёмкостью, а тем, где стоит денойзер. Post-денойзер работает напрямую с артефактами выхода ADMM, тогда как pre-денойзер "чистит" измерение ещё до плохо обусловленной инверсии, и его эффект частично смывается последующим ADMM.

Также такой буст в качестве можно объяснить главной проблемой, которая делала метрики не такими хорошими, как мы бы хотели, - это яркость изображений. Одна из задач денойзера - корректировка масштаба и яркости изображения. Если денойзер стоит перед ADMM, то ему сложнее корректировать яркость, так как модель может её сильно испортить после корректировки. Если же денойзер стоит после ADMM, то ему легче подстроить яркость под подсчет метрик и лосса, так как он является заключительным звеном в цепи и его выходы больше не подвержены никакому искажению.

### Удвоение числа денойзеров - почти не двигает метрику

`Modular Pre-Post` добавляет второй денойзер: это 9 191 258 параметров - на **+12.5%** больше, чем у одиночного денойзера. Прибавка к лучшему одиночному варианту (Post):

| | PSNR $\uparrow$ | SSIM $\uparrow$ | LPIPS $\downarrow$ | MSE $\downarrow$ |
|---|---|---|---|---|
| Modular Post (8 167 319) | 15.953 | 0.431 | 0.550 | 0.028 |
| Modular Pre-Post (9 191 258) | 16.554 | 0.458 | 0.527 | 0.025 |
| $\Delta$ | +0.60 | +0.027 | -0.023 | -0.003 |

+12.5% параметров $\rightarrow$ всего +0.6 к PSNR - **сильно убывающая отдача**. Причём pre-post - это не "вдвое больше ёмкости": общий бюджет ($\sim 9.2$ M) лишь немного выше одиночного ($\sim 8.2$ M), просто он **разбит на две меньшие сети** ($h = 24$, по $\sim 4.6$ M каждая) вместо одной большой ($h = 32$). То есть каждый денойзер в pre-post **слабее** одиночного, и тем не менее pre-post всё равно выигрывает - именно потому, что чистит картинку и до, и после инверсии. Снова: выигрыш приносит **покрытие/размещение**, а не количество весов.

### Вывод

Порядок моделей (Post $\gg$ Pre при равных параметрах; Pre-Post лишь чуть выше Post при +12.5% весов) объясняется архитектурой, а не ёмкостью. Это ровно тезис модульного подхода Bezzam: ключевую работу делает **post-обработка выхода инверсии**, а не размер денойзеров. Дополнительный приятный бонус денойзеров, который мы можем проследить в качественном анализе изображений, - они **сами подстраиваются под яркость**: одиночному ADMM нужна внешняя нормировка выхода, а модульные модели приводят выход к нужному масштабу самостоятельно.

> Ниже - разбор кривых из Comet; Все наблюдения были сделаны на основе репорта, который я сделал в Comet. В нем отражены графики train, test и окончательные результаты, а также несколько примеров восстановленных изображений.

> Ссылка на репорт: https://www.comet.com/german-zverev/lensless-computational-imaging/reports/oeWU5PMXevvdRl12v5meJPp2u

**Важное замечание по оси OX:** `ADMM-Unrolled` обучался с `batch_size = 2` на Каггле, остальные - с `batch_size = 4`. Поэтому при одинаковом числе эпох у unrolled вдвое больше шагов, и его кривая на графиках «VS step» растянута вширь примерно в 2 раза (тянется до $\sim 45$ k, тогда как модульные заканчиваются на $\sim 30$ k). Сравнивать модели по шагам напрямую некорректно - по эпохам длительность сопоставима.

**Train.**
- `loss_train`, `lpips_train`, `mse_train` монотонно убывают у всех моделей; три модульные кривые уходят заметно ниже unrolled, который выходит на плато высоко (loss $\sim 0.7$, mse $\sim 0.22$). Также стоит сказать, что модульные модели показывают уже на первых двух эпохах($\sim 4.5k$ шагов), а потом скорость улучшения метрик затухает - хороший показатель того, насколько быстрее и качественнее модульные модели движутся к оптимуму. Эти оценки согласуются с тем, что unrolled застревает на уровне классической инверсии.
- Про качество и скорость сходимости `psnr_train` можно сказать то же самое, что и про остальные метрики, поэтому анализ `psnr_train` я опущу.
- `grad_norm_train` наглядно показывает то, как себя ведет процесс обучения: у модульных моделей норма градиента упирается в потолок `max_grad_norm` и держится в районе $0.6$-$1.0$ (работает клиппинг), а у unrolled она прижата почти к нулю - это следствие лог-параметризации (градиент по $\log\mu$ масштабируется на $\mu \approx 10^{-4}$). До клиппинга нормы градиентов лежали в диапазоне $[2, 3]$, что давали сходимость хуже при константном lr = 1e-4.

**Test.**
- `psnr_test`: `Modular Pre-Post` и `Modular Post` идут вверху и близко друг к другу ($\sim 16.2$ и $\sim 15.5$), `Modular Pre` отстаёт ($\sim 13.0$), а `Unrolled` медленно ползёт с $\sim 8.5$ до $\sim 11.0$. Заметим, что поведение и относительный прядок кривых на тесте совпадают с кривыми на трейне(конечно же есть взять только метрики в конце каждой эпохи). Это является показателем того, что мы не ловим явное переобучение и стабильно двигаемся к оптимуму.
- `SSIM_test`: Pre-Post и Post поднимаются к $\sim 0.43-0.46$, Pre - к $\sim 0.22$, Unrolled почти плоский на $\sim 0.18$ (ниже даже ADMM-100). Эти результаты говорят о том, что Pre-Post и Post улавливают главную суть, которую мерит SSIM - то, насколько пиксели структурно похожи на оригинальное изображение и то, насколько соблюдены локальные зависимости между пикселями.
- `LPIPS_test` / `MSE_test` - зеркально убывают; модульные уверенно ниже unrolled, который держится на $\sim 0.75$, почти не падая. Это показывает превосходство модульных моделей в "человеческом" восприятии качества реконструкции, так как LPIPS направлена на измерение визуальных изменений.
- Панели `n_params_*` подтверждают бюджеты: `n_params_admm` ничтожен (десятки), `n_params_pre`/`n_params_post` $\sim$ 8.2M.

Общая картина кривых согласуется с выводами разделов 3 и 5: денойзеры (особенно post) дают основной прирост, а само разворачивание ADMM почти не отрывается от бейзлайна.

## 8. Главные выводы

1. **Масштаб выхода и порядок операций критичны.** Нормировку для метрик нужно делать после backward, иначе теряется сигнал по яркости в MSE - это разница между PSNR 6.5 и адекватными числами около 10.
2. **Параметризация важнее, чем кажется.** Лог-параметризация $\mu, \tau$ - единственный способ удержать ADMM от расходимости.
3. **Правильная обработка данных.** Самое дорогое место - не сама модель, а симуляция PSF; кеш в датасете дал кратное ускорение.
4. **Gradient clipping для разворачиваемых алгоритмов почти обязателен** из-за плохо обусловленных градиентов FFT-операторов.
5. **Денойзеры компенсируют слабости классической инверсии**, в том числе подстройку под яркость, что и есть основной посыл модульного подхода Bezzam.
6. **Размещение денойзера важнее числа параметров.** При равных 8.2M параметров post-вариант обходит pre-вариант на 2.6, а удвоение сети в pre-post (+12.5% весов) добавляет лишь 0.6 - ёмкость почти не объясняет результат, объясняет архитектура.
